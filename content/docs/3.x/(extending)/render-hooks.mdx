---
title: Render Hooks
description: Inject custom HTML, Livewire components, or Blade views into specific positions across the admin panel without modifying Shopper's core views.
---

Render hooks give you named injection points inside Shopper's admin views. Instead of overriding templates, you register a callback on a hook name and Shopper renders your content in the right place at the right time.

This is the recommended way to add content to an admin page: a banner in the sidebar of the order page, a widget above the product list, or a tracking script in the page head.

## Registering a Hook [#registering-a-hook]

Your application registers hooks on the admin panel through the `Shopper` facade, in the `boot()` method of a service provider:

```php title="app/Providers/AppServiceProvider.php"
use Shopper\Facades\Shopper;
use Shopper\View\OrderRenderHook;

public function boot(): void
{
    Shopper::renderHook(
        OrderRenderHook::DETAIL_SIDEBAR_AFTER,
        fn (): string => '<p class="text-sh-fg-muted text-sm">Ships from the Lyon warehouse.</p>',
    );
}
```

The text shows at the end of the sidebar of the order page, below the billing address:

<Screenshot src="/images/v3/extending-render-hook.png" alt="Customer sidebar of an order with the line Ships from the Lyon warehouse below the billing address" />

The callback receives no arguments. Shopper casts what it returns to a string and outputs it as HTML without compiling it with Blade, so return plain HTML, a view, or a Livewire component rendered with `Blade::render()`. The HTML is not escaped: pass any value that comes from a record or a request through `e()`, or render it in a view with `{{ }}`.

An add-on registers its hooks with `$panel->renderHook()` in the `register()` method of its add-on class, as described in [Render Hooks](/3.x/addons/admin-panel#render-hooks) of the add-on guide.

### Returning a Blade View [#returning-a-blade-view]

A view is rendered when Shopper casts it to a string, so the callback can return it as is:

```php title="app/Providers/AppServiceProvider.php"
use Illuminate\Contracts\View\View;
use Shopper\Facades\Shopper;
use Shopper\View\ProductRenderHook;

Shopper::renderHook(
    ProductRenderHook::EDIT_CONTENT_AFTER,
    fn (): View => view('shopper.products.seo-checklist'),
);
```

### Returning a Livewire Component [#returning-a-livewire-component]

Because Shopper does not compile the output with Blade, a `<livewire:...>` tag returned as a string is printed as is. Render the tag with `Blade::render()`:

```php title="app/Providers/AppServiceProvider.php"
use Illuminate\Support\Facades\Blade;
use Shopper\Facades\Shopper;
use Shopper\View\CustomerRenderHook;

Shopper::renderHook(
    CustomerRenderHook::SHOW_SIDEBAR_AFTER,
    fn (): string => Blade::render('<livewire:customer-loyalty-points />'),
);
```

The callback cannot pass the customer to the component. The [example below](#example-injecting-an-external-status-badge-on-order-detail) shows how a component reads the record of the page from the route.

### Registering Multiple Hooks [#registering-multiple-hooks]

`renderHook()` returns the panel, so you can chain several calls:

```php title="app/Providers/AppServiceProvider.php"
use Shopper\Facades\Shopper;
use Shopper\View\LayoutRenderHook;

Shopper::renderHook(
    LayoutRenderHook::HEAD_END,
    fn (): string => '<script src="https://cdn.example.com/analytics.js" defer></script>',
)->renderHook(
    LayoutRenderHook::BODY_START,
    fn (): string => view('analytics.noscript-tag')->render(),
);
```

Multiple callbacks registered on the same hook are rendered in the order they were registered, concatenated together.

## Disabling a Hook [#disabling-a-hook]

Hooks registered by an add-on follow the add-on's enabled state: a [disabled add-on](/3.x/addons#disabling-an-addon) registers none. For the hooks of your application, register them under a condition:

```php title="app/Providers/AppServiceProvider.php"
use Shopper\Facades\Shopper;
use Shopper\View\OrderRenderHook;

if (config('features.custom_order_widget')) {
    Shopper::renderHook(
        OrderRenderHook::DETAIL_MAIN_AFTER,
        fn (): string => view('orders.external-status')->render(),
    );
}
```

## Available Hooks [#available-hooks]

Each hook is a constant of a class in the `Shopper\View` namespace. The tables give the hook name behind each constant and the place where it renders.

The callbacks of a hook run each time the view that holds it renders. Hooks inside a Livewire page, such as the dashboard or the order page, run again when the page re-renders after an action, so keep their queries short.

### Layout Hooks [#layout-hooks]

`LayoutRenderHook` covers the global admin layout present on every page.

| Constant | Hook Name | Position |
|----------|-----------|----------|
| `HEAD_START` | `shopper::head.start` | In `<head>`, after the meta tags and fonts, before the Filament styles and the Shopper theme |
| `HEAD_END` | `shopper::head.end` | In `<head>`, after the Shopper theme, scripts and extra stylesheets |
| `BODY_START` | `shopper::body.start` | Right after `<body>` |
| `BODY_END` | `shopper::body.end` | Right before `</body>`, after the slide-over panels and the scripts |
| `BEFORE_HEADER` | `shopper::header.before` | Above the top bar |
| `AFTER_HEADER` | `shopper::header.after` | Below the top bar |
| `HEADER_START` | `shopper::header.start` | In the top bar, before the notifications, the site link and the account menu |
| `HEADER_END` | `shopper::header.end` | In the top bar, after `HEADER_START` and before the notifications |
| `SIDEBAR_START` | `shopper::sidebar.start` | At the top of the sidebar navigation |
| `SIDEBAR_END` | `shopper::sidebar.end` | At the bottom of the sidebar navigation |
| `CONTENT_START` | `shopper::content.start` | Above the content of the page |
| `CONTENT_END` | `shopper::content.end` | Below the content of the page |
| `CONTENT_ASIDE` | `shopper::content.aside` | Next to the content of the page, for a side panel |
| `DASHBOARD_START` | `shopper::dashboard.start` | Top of the dashboard page |
| `DASHBOARD_END` | `shopper::dashboard.end` | Bottom of the dashboard page |
| `ACCOUNT_START` | `shopper::account.start` | Top of the account page |
| `ACCOUNT_END` | `shopper::account.end` | Bottom of the account page |

The `HEAD` and `BODY` hooks also render on the sign-in pages. Check `shopper()->auth()->check()` in the callback before rendering content meant for signed-in users. The settings index page has no hooks: `SETTINGS_INDEX_START` and `SETTINGS_INDEX_END` do not exist in 3.x.

## Example: Injecting an External Status Badge on Order Detail [#example-injecting-an-external-status-badge-on-order-detail]

A real-world scenario: your store syncs orders to a fulfillment service (ShipStation, ShipBob, etc.) and you want to display the external status directly on the order detail page, without modifying any Shopper files.

The hook callback receives no arguments, so it cannot pass the order to your component. Instead, the hook renders a Livewire component that reads the order from the current route in its `mount()` method. The order detail route is `{order}/detail`, and the order detail page resolves `{order}` to the `Order` model. Livewire keeps the component's state on later requests, so `mount()` only runs on the page load.

Create the Livewire component:

```php title="app/Livewire/ExternalOrderStatus.php"
namespace App\Livewire;

use App\Services\ExternalFulfillmentService;
use Illuminate\Contracts\View\View;
use Livewire\Attributes\Locked;
use Livewire\Component;

class ExternalOrderStatus extends Component
{
    #[Locked]
    public int $orderId;

    public function mount(): void
    {
        $this->orderId = request()->route('order')->id;
    }

    public function render(): View
    {
        $status = ExternalFulfillmentService::getStatus($this->orderId);

        return view('livewire.external-order-status', ['status' => $status]);
    }
}
```

Register the hook in your service provider:

```php title="app/Providers/AppServiceProvider.php"
use Illuminate\Support\Facades\Blade;
use Shopper\Facades\Shopper;
use Shopper\View\OrderRenderHook;

public function boot(): void
{
    Shopper::renderHook(
        OrderRenderHook::DETAIL_SIDEBAR_AFTER,
        fn (): string => Blade::render('<livewire:external-order-status />'),
    );
}
```

## Using Hook Constants vs. Raw Strings [#using-hook-constants-vs-raw-strings]

Always use the class constants instead of raw hook name strings. They are checked by static analysis, will trigger IDE autocompletion, and won't silently break if a hook name changes in a future release. Both calls below register on the same hook:

```php title="app/Providers/AppServiceProvider.php"
use Shopper\Facades\Shopper;
use Shopper\View\ProductRenderHook;

Shopper::renderHook(ProductRenderHook::EDIT_CONTENT_AFTER, fn (): string => '<p>Reviewed by the catalog team</p>');

Shopper::renderHook('shopper::product.edit.content.after', fn (): string => '<p>Reviewed by the catalog team</p>');
```
